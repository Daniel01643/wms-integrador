## Fatos do código que fundamentam o plano
- `ResultadoIntegracaoNota` é `sealed record` posicional (NumeroNota, NumeroTransporte, Integrada, Tentativas, Estado, UltimaMensagem, Historico). É construído só em 4 pontos de `Orquestrador.IntegrarNotaAsync` (sem transporte, sucesso, pendência, erro genérico, esgotou tentativas = 5 `return`s). Não há ponto de código que converta Resultado -> `LinhaRelatorioErro` (nenhum chamador do `IGeradorRelatorio` além do registro em `Worker\Program.cs`); só os testes usam o gerador.
- Estado híbrido: sucesso após I30 => `Integrada=true`, `Estado=Pendente` (`pendenteRevisaoProduto`). Não mudar essa regra.
- `RespostaWms.Transacao` (string) e `RetornoWms.IdDocumento` (string) já existem; `Orquestrador` hoje só usa `PrimeiraMensagem`. Códigos de produto: `NotaFiscal.Itens[].CodigoProduto` (`ItemNota`). O I30 é enviado para TODOS os itens da nota.
- `GeradorRelatorio` hoje: HTML mínimo; PDF 1 página portrait, colunas fixas, `GlobalFontSettings.FontResolver ??= new PdfSharpCore.Utils.FontResolver()` no ctor estático. `OpcoesRelatorio` só tem `PastaSaida`. `appsettings.json` (Worker) tem seção `Relatorio` com `_comentario` e `PastaSaida`.
- Exemplos antigos: `docs\exemplos\relatorio-erros-exemplo.html/.pdf` (sem script gerador no repo).

## Decisões de design (curtas)
1. Captura de transação/idDocumento/produtos: propriedades `init` NOVAS com default em `ResultadoIntegracaoNota` (não alteram o construtor posicional, logo os 109 testes e os `new` seguem compilando). Valor vem da ÚLTIMA resposta da I50 (é o erro exibido). O fluxo de decisão não é tocado: só variáveis locais de captura + `with`/initializer nos `return`s.
2. Produtos provisórios: no ramo `EhProdutoNaoCadastrado`, acumular `nota.Itens.Select(CodigoProduto)` distintos (lista de todos os enviados ao I30; o WMS não diz quais eram novos — documentar). `RevisaoProdutoPendente = ProdutosProvisorios.Count > 0` (vale mesmo se a nota acabar não integrada, pois o cadastro provisório existe). Texto de status "Integrada — revisar produto" só quando `Integrada && RevisaoProdutoPendente`.
3. Relatório consome `LinhaRelatorioErro` (interface `IGeradorRelatorio` mantém as 3 assinaturas). Um `ModeloRelatorio` interno (resumo + grupos + produtos a revisar) é montado uma vez e usado pelos dois renderizadores, garantindo números idênticos em HTML e PDF.
4. Horário não existe no Resultado: o mapeador recebe o horário (IClock) como parâmetro.
5. PDF em duas passadas (layout -> desenho) para saber o total de páginas no rodapé "Página X de Y".
6. Tudo no PDF com Arial; sem novas dependências NuGet.

## Lacunas / suposições
- O Resultado não traz horário: usa-se o horário injetado ao mapear (suposição: horário do processamento da nota).
- Lista de produtos provisórios = todos os itens enviados ao I30 (o WMS responde um por vez/"já existe"; não há como distinguir os realmente criados).
- Cores de status âmbar/vermelho são semânticas, fora da paleta Friozem.
- Em ambientes sem Arial (Linux CI), `FontResolver` padrão pode falhar; o Worker roda em Windows Server, então Arial está disponível; testes de PDF assumem Windows (como hoje).
- O acoplamento `Estado=Pendente` + `Integrada=true` NÃO é alterado no Orquestrador; a distinção é resolvida só na apresentação (observação 1 da revisão da etapa 6). Observação 2 (`PreCondicaoOk`) permanece fora do escopo.
