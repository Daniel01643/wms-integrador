# Plano de implementação: Puxada e Puxada TSP (ZIP por pasta)

Fonte: `docs/ESCOPO-PUXADA-TSP.md` (seção 6) + decisões de 12/11/2026 (raiz com Origem, prefixo `TSP-`, horas).
Projeto C#/.NET 8, branch `main`, sem worktree, **commits locais pequenos, sem push**.
Comandos reais: `dotnet build -c Debug`, `dotnet build -c Release`, `dotnet test` (base: 487 aprovados + 9 ignorados).
Esforço só em horas (humanas x IA); nunca valores monetários; não inventar horas humanas.

Contratos dos loops existentes (mantidos, este plano NÃO reestrutura o workflow):
- `code-loop` para quando `.agents/tasks/review-codigo.json` tiver `verdict: APPROVED`.
- `docs-loop` para quando `.agents/tasks/review-docs.json` tiver `verdict: APPROVED`.
- Revisor sempre por último no loop. Decisão: o trabalho é sequencial e acoplado (config -> tipo -> ZIP -> onda -> relatório), então não decompus em FEATs; os loops atuais implementam este plano por itens.

## O que a exploração mostrou (código lido)

- Não há `FileSystemWatcher`: o "watcher" é o polling de `GerenciadorPacote.CicloAsync`, que lista só a raiz da entrada via `ClassificarEntrada()`/`ListarEntrada()` (`Directory.EnumerateFiles(entrada, TopDirectoryOnly)` + `ClassificadorEntrada.Classificar`). Foto = lista de caminhos prontos (`DetectorArquivoPronto.Avaliar`), `ProcessadorLote.ProcessarAsync(arquivos, idPacote)` e `ProcessarNaoXml`.
- `ProcessadorLote` faz parse -> `AgrupadorTransporte.Agrupar` (por `NotaFiscal.NumeroTransporte`) -> `ProcessarOndaAsync` chama `IOrquestrador.IntegrarAsync(new[]{nota}, transporte)`. O `Orquestrador` usa esse 2º argumento como `nroagrupseparacao` e também `numeroPlanejamento` (`ConstrutorI50.Construir(nota, transporte)`); só marca "sem transporte" se o argumento for vazio.
- `OrganizadorArquivos.Mover(arquivo, destino, categoria, motivo, idPacote)` move para `Processados\<id>\` ou `Erro\<id>\<Categoria>\` mantendo o nome do arquivo (`CaminhoUnico`). `LocalizadorXmlDevolucao` procura `NFE<chave>.XML` em `Processados\pacote_*\` (TopDirectoryOnly) e já ignora outros arquivos, então guardar o `.zip` ao lado dos XMLs é seguro, desde que o XML continue direto em `pacote_*\`.
- `RegistroDiario` (record posicional, JSONL em `Estado\pacote-atual.jsonl`) -> `ParaLinha()` -> `LinhaRelatorioErro` (record posicional) -> `ModeloRelatorio.Montar` (agrupa por `NumeroTransporte`; `ResumoRelatorio` com `Transportes`, `NotasPorTransporte`) -> `RenderizadorHtml` (colunas: Nota, Transporte, Horário, Status, ID, ...; `tr.grupo`), `RenderizadorPdf` (`Cabecalhos`/`Larguras`, coluna 5 = Mensagem elástica), `CorpoEmailResumo` (cartões + tabela de problemas), `MapeadorTelemetria`/`RegistroTelemetria`, `CorpoEmailResumoSemanal`/`ResumoPeriodo`/`AgregadorTelemetria`.
- `ConsolidadorRegistros` deduplica por `Arquivo` (caminho). Arquivos extraídos terão caminhos únicos em `Estado\tmp\...`, sem conflito.
- Testes: `tests/KitWmsIntegrador.Tests/Infra/AmbientePacote.cs` (pilha completa em pasta temporária, `FakeClock`, `OrquestradorFalso`, `Xml(numero, transporte)` sintético, `new ProcessadorLote(...)` e `new GerenciadorPacote(...)` com construtor posicional), `ExemplosRelatorio.cs`, `GeradorRelatorioTests`, `CorpoEmailResumoTests`, `ClassificadorEntradaTests`, `OpcoesPastaValidacaoTests`, `Stress/*`. ## Decisões de projeto (com motivo)

1. **Origem x Tipo**: `Origem` ∈ {`raiz`, `Puxada`, `PuxadaTSP`} (rótulo = nome da pasta configurada para as duas subpastas); `Tipo` ∈ {`PUXADA`, `TSP`}. Tipo vem da origem: `PuxadaTSP` -> TSP; `Puxada` e `raiz` -> PUXADA. Motivo: regra única, sem detecção.
2. **Tipos novos num arquivo só** em `Core/Pacote/TipoNota.cs` (enum `TipoNota { Puxada, Tsp }` com `Rotulo()` = "PUXADA"/"TSP") e `OrigemEntrada.cs` (record `EntradaArquivo(string Caminho, TipoNota Tipo, string Origem)`). Campos novos em `RegistroDiario` e `LinhaRelatorioErro` entram **no fim, com default** (`Tipo = "PUXADA"`, `Origem = ""`, `Onda = ""`, `Zip = ""`) para o diário antigo e os testes atuais continuarem compilando e lendo JSON.
3. **ZIP**: classe nova `Core/Pacote/LeitorZipSeguro.cs` (System.IO.Compression, sem NuGet). Extrai para `Estado\tmp\<guid>\`, achatando nomes (só `Path.GetFileName`), ignora entradas com `..`, caminho absoluto, `:` ou diretório; só `.xml` (case-insensitive); outra extensão vira registro `ExtensaoInvalida` (sem abrir); `.zip` aninhado = `ExtensaoInvalida` (não abre). Limites `Zip:MaxArquivos` (padrão 1000) e `Zip:MaxTamanhoMb` (padrão 500), checados pelo tamanho declarado E contando bytes realmente copiados (proteção contra ZIP bomba que mente no cabeçalho). ZIP corrompido, vazio de XML ou protegido por senha -> exceção tratada vira `CategoriaErro.ZipInvalido`.
4. **Layout preservado**: XMLs extraídos são movidos, um a um, por `OrganizadorArquivos` para `Processados\pacote_*\` (ou `Erro\...`) com o nome do arquivo no ZIP (achatado, `CaminhoUnico` evita colisão); o `.zip` original é movido para o mesmo `Processados\pacote_*\` (ou `Erro\pacote_*\ZipInvalido\` + `.motivo.txt`) **depois** que todos os XMLs dele foram tratados. Pasta `Estado\tmp\<guid>` é apagada no `finally`. Se cair no meio, o ZIP continua na entrada e é reprocessado; o WMS barra duplicata e a onda se repete pelo hash.
5. **XML repetido** (mesma `ChaveNFe` dentro da mesma foto, em ZIPs ou arquivos diferentes): processa o primeiro; o repetido não vai ao WMS e gera registro `Integrada=false`, `Status=ArquivoIgnorado`, mensagem "XML repetido (chave já processada neste pacote)", destino `Processados` (não é erro de integração) e categoria nula, para não poluir `Erro`. Fica contado como "arquivo ignorado" no resumo, com o motivo no relatório.
6. **XML solto na PuxadaTSP** (e qualquer não-ZIP lá) -> `ExtensaoInvalida` com motivo "A pasta PuxadaTSP aceita apenas ZIP". Motivo: sem ZIP não há nome de onda; o relatório mostra. ZIP na raiz da entrada: aceito como PUXADA, Origem `raiz` (coerente com a regra da raiz).
7. **Nome da onda** em `Core/Pacote/NomeadorOndaTsp.cs` (puro, testável) + `Core/Pacote/RegistroOndasTsp.cs` (persistência). Formato final **`TSP-AAAAMMDD-NN-NOME`**. Prefixo `TSP-` constante pública `NomeadorOndaTsp.Prefixo` (fixa no código, sem opção). Parte fixa = 16 caracteres; **NOME cortado para no máximo 14** (total <= 30). Sem nome: `TSP-AAAAMMDD-NN` (15). Limpeza do NOME: tira extensão, remove as palavras `XML`/`XMLS` (palavra inteira, após remover apóstrofo: `XML'S` vira `XMLS`), apóstrofos (`'`, `´`, `` ` ``, `’`), maiúsculas, remove acentos (normalização FormD), só `A-Z0-9-`, espaços viram `-`, colapsa hífens repetidos e apara hífens das pontas; corte em 14 reaparando hífen final. Exemplos: `XML'S SOROCABA.zip` -> `SOROCABA`; `XML'S SJC.zip` -> `SJC`; `XML'S.zip` -> vazio -> `TSP-20261111-01`.
8. **Sequencial e reprocesso**: arquivo JSON `Estado\tsp\ondas.json` (`{ "data":"AAAAMMDD", "ultimo":N, "ondas":{ "<sha256 do conteúdo do ZIP>":"TSP-..." } }`, gravação atômica via arquivo temporário + `File.Move(overwrite)`, lock em memória). Data = `IClock.UtcNow.ToLocalTime()` (relógio do servidor). Hash já presente => devolve a mesma onda sem consumir sequencial (mesmo em outro dia). Hash novo => `ultimo+1` (reinicia em 1 quando a data muda), `NN` com 2 dígitos (>99 passa para 3 dígitos; o corte do NOME se ajusta para manter <= 30). Mapa de hashes de dias anteriores é podado após 90 dias para não crescer (guardar `data` por hash). `Estado` já é protegido da limpeza (validação existente).
9. **Agrupamento**: `AgrupadorTransporte` fica **inalterado** para PUXADA. Para TSP o `ProcessadorLote` cria **uma onda por ZIP** diretamente (lista de notas do ZIP, na ordem), sem passar pelo agrupador por transporte. Chamada ao orquestrador: `IntegrarAsync(new[]{nota}, nomeDaOnda)`; isso faz `nroagrupseparacao` = nome da onda e, sem mudar a interface `IOrquestrador` nem o `ConstrutorI50`, `numeroPlanejamento` também = nome da onda (hoje ele repete o agrupador). **Premissa a validar no homolog** (registrar em OPERACAO/ESCOPO). Nota TSP sem transporte sobe normalmente (argumento não vazio). DocCarga continua 1 por nota.
10. **Transporte exibido na TSP**: o `ResultadoIntegracaoNota.NumeroTransporte` volta com o nome da onda; o `ProcessadorLote` grava no `RegistroDiario` `NumeroTransporte = nota.NumeroTransporte ?? ""` (rótulo "(sem)" na TSP) e `Onda = nome da onda`. Na PUXADA nada muda (`NumeroTransporte` = transporte, `Onda` vazia).
11. **Paralelismo**: ondas TSP entram na mesma fila `SemaphoreSlim(MaxTransportesConcorrentes)` das ondas de transporte (uma tarefa por ZIP, notas em sequência), como hoje.
